# UI & Styling Specification — Tango (Web Port)

## 1. Goal

Adapt the visual language of `base_stylesheet/style.css` (the existing
Minesweeper game) to the Tango game, so the two games feel like part of the same
suite. Reuse the base design tokens, layout primitives, buttons, and dialogs;
extend them only where Tango needs new concepts (sun/moon symbols, fixed cells,
edge-clue badges, invalid highlighting).

The visual direction is: **dark page, light board cells, flat surfaces, 6–10 px
radii, `system-ui` stack, restrained accent color.**

Base CSS variables reused: `--cell-size`, `--cell-font`, `--covered`,
`--covered-hover`, `--revealed`, `--border`.

## 5. Board and cells

### 5.1 Board grid

```css
.board {
  display: grid;
  grid-template-columns: repeat(6, var(--cell-size));
  grid-template-rows: repeat(6, var(--cell-size));
  gap: var(--edge-gap);
  padding: 8px;
  background: var(--border);
  border-radius: 6px;
}
```

The board background (`--border`) shows through the gaps as grid lines. Gaps are
slightly wider than the base's 1 px so edge-clue badges have room to sit on the
lines.

### 5.2 Cell base

Reuse `.cell` from the base (`--covered` background, rounded, centered, pointer).
Add:

```css
.cell { position: relative; }
.cell .symbol {
  width: 64%;
  height: 64%;
  object-fit: contain;
  pointer-events: none;
  user-select: none;
}
```

### 5.3 Cell states

| State | Class | Visual |
|-------|-------|--------|
| Empty (playable) | `.cell` | Base `--covered` background; hover `--covered-hover`. |
| Fixed / given | `.cell.fixed` | `background-color: var(--fixed-cell)`; default cursor; no hover change. |
| Sun | `.cell` + `<img class="symbol" src="assets/sun.svg">` | Yellow sun SVG. |
| Moon | `.cell` + `<img class="symbol" src="assets/moon.svg">` | Dark-navy crescent SVG. |
| Invalid | `.cell.invalid` | Red tint overlay + inset red ring. |
| Solved/locked | board-wide (`won`) | Input ignored; overlay shown (no special cell class required). |

Recommended CSS:

```css
.cell.fixed {
  background-color: var(--fixed-cell);
  box-shadow: inset 0 0 0 2px rgba(70, 80, 95, 0.28);
  cursor: default;
}
.cell.fixed:hover { background-color: var(--fixed-cell); }

.cell.invalid {
  background-image: linear-gradient(var(--invalid-tint), var(--invalid-tint));
  box-shadow: inset 0 0 0 2px var(--invalid-ring);
}
.cell.invalid:hover {
  background-image: linear-gradient(var(--invalid-tint), var(--invalid-tint));
}
```

The red tint is a `background-image` overlay so it layers **under** the
`<img class="symbol">` content (matching the reference, which draws the invalid
highlight before the symbols). It composes with `.cell.fixed` because fixed sets
`background-color` while invalid sets `background-image`.

## 6. Sun and moon symbols

- Use the provided assets **as-is**: `assets/sun.svg` and `assets/moon.svg`.
- Render as `<img class="symbol" src="assets/sun.svg" alt="Sun"
  draggable="false">` (and `alt="Moon"` for the moon). Use empty/false
  `pointer-events` so clicks land on the cell.
- The base cells are light (`#b8bfc9`), so both the yellow sun and the dark-navy
  moon have sufficient contrast; **do not recolor** the SVGs.
- Sizing: ~64% of the cell, centered, `object-fit: contain`.

## 7. Edge-clue badges

Edge clues (`=` / `X`) are rendered as small circular badges centered on the
grid line between two adjacent cells, mirroring the reference's
`_dibujar_badge_borde`.

**Implementation:** each badge is a child of the cell on its left (for
horizontal edges) or above (for vertical edges), absolutely positioned to
overflow into the gap. This avoids JS position math and stays responsive to
`--cell-size` / `--edge-gap`.

DOM (inside a cell):

```html
<span class="edge-hint edge-hint--right" aria-hidden="true">=</span>
<span class="edge-hint edge-hint--bottom" aria-hidden="true">X</span>
```

- Horizontal edge between `(r,c)` and `(r,c+1)` → badge appended to cell `(r,c)`
  with `edge-hint--right`.
- Vertical edge between `(r,c)` and `(r+1,c)` → badge appended to cell `(r,c)`
  with `edge-hint--bottom`.

CSS:

```css
.edge-hint {
  position: absolute;
  z-index: 2;
  display: flex;
  align-items: center;
  justify-content: center;
  width: var(--badge-size);
  height: var(--badge-size);
  border-radius: 50%;
  background: var(--badge-bg);
  border: 1.5px solid var(--badge-border);
  color: var(--badge-text);
  font-size: 12px;
  font-weight: 700;
  line-height: 1;
  pointer-events: none;
}
.edge-hint--right {
  left: calc(100% + var(--edge-gap) / 2);
  top: 50%;
  transform: translate(-50%, -50%);
}
.edge-hint--bottom {
  top: calc(100% + var(--edge-gap) / 2);
  left: 50%;
  transform: translate(-50%, -50%);
}
```

Notes:

- `--edge-gap` is defined on `.board` and inherited by cells.
- Badges may overlap cell edges slightly; `z-index: 2` keeps them above cell
  backgrounds. Symbols are centered at 64% size so they are not obscured.
- Badges are decorative for assistive tech (`aria-hidden="true"`); the same
  information can be exposed via cell `aria-label` if desired.

## 8. Responsive sizing

Adapt the base's `updateCellSize()` for a 6×6 board:

```js
const CELL_MIN = 40;
const CELL_MAX = 72;

function updateCellSize() {
  const availW = Math.min(window.innerWidth - 48, 1200);
  const availH = window.innerHeight - 210; // topbar + status + padding
  const byWidth  = (availW - (N - 1) * EDGE_GAP) / N;
  const byHeight = (availH - (N - 1) * EDGE_GAP) / N;
  let size = Math.floor(Math.min(byWidth, byHeight));
  size = Math.max(CELL_MIN, Math.min(CELL_MAX, size));
  boardEl.style.setProperty("--cell-size", size + "px");
  boardEl.style.setProperty("--cell-font", Math.max(10, Math.round(size * 0.4)) + "px");
}
```

Recompute on `resize`. The board stays square and centered; the page must remain
usable on small viewports (the board may shrink to `CELL_MIN`).

## 9. Win overlay

Reuse the base result-dialog pattern:

- Hidden by default (`hidden` attribute).
- On win: set `#win-summary` to include the elapsed time (e.g., `Solved in
  01:23`), remove `hidden`, and focus `#play-again`.
- Title `#win-title` uses `.dialog__title.is-won` (green, per base).
- `#play-again` triggers `newPuzzle()` and hides the overlay.
- The board remains visible behind the dimmed backdrop and is locked.

Suggested content:

- Title: **"You solved it!"**
- Subtitle: **"Solved in MM:SS · 6×6"** (optional attempts/clues detail).
- Button: **"New game"**.

## 10. Status bar behavior

- `#remaining` shows the count of empty cells (updated after every change).
- `#timer` shows `MM:SS`, running from the moment a puzzle is displayed, updated
  ~5×/second.
- `#status-message` shows transient text: "Generating…" before generation;
  optional "Solved!" on win; cleared on new/reset.

## 11. Interactions visual feedback

| Situation | Feedback |
|-----------|----------|
| Hover playable cell | `--covered-hover` background. |
| Hover fixed cell | None (cursor default). |
| Invalid cell | Red tint + ring, persists while invalid. |
| Valid move | Immediate symbol render; remaining count updates. |
| Win | Timer stops, board locks, overlay fades in (optional ~600 ms delay to show the final board). |
| Generating | "Generating…" status; buttons disabled/ignored. |

## 12. Accessibility

- `#board` uses `role="grid"` with `aria-label="Tango puzzle board"`; cells use
  `role="gridcell"` and an `aria-label` describing coordinates, state, and fixed
  status (e.g., `"Row 2, column 3, sun, given"`).
- Buttons have clear text labels; the overlay is `role="dialog"` with
  `aria-modal="true"` and `aria-labelledby`.
- Keyboard: `N` new, `R` reset. (Cell navigation via keyboard is not required by
  the reference; tab order should at least reach the buttons.)
- Symbols use `alt="Sun"` / `alt="Moon"`; edge badges are `aria-hidden` (their
  constraint can be conveyed via cell labels if implemented).

## 13. Acceptance criteria (UI)

- **AC-U1** Sun and moon are rendered from `assets/sun.svg` / `assets/moon.svg`
  (not geometric CSS shapes).
- **AC-U2** Each edge clue appears as a circular `=` / `X` badge centered on the
  line between its two cells.
- **AC-U3** Fixed cells are visually distinct from playable empty cells.
- **AC-U4** Invalid cells are highlighted in red in real time and revert when
  the violation is resolved.
- **AC-U5** The board auto-fits the viewport, stays square, and respects
  `CELL_MIN`/`CELL_MAX`.
- **AC-U6** The page uses the base stylesheet's dark theme, typography, button
  styles, and dialog styling (visually consistent with the Minesweeper game).
- **AC-U7** The win overlay matches the base result dialog and offers a working
  "New game" action.
- **AC-U8** The status bar shows remaining count and a running `MM:SS` timer.
